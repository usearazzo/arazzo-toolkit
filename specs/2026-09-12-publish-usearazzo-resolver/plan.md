# Phase 1 Plan — Publish @usearazzo/resolver

## Group 1 — Resolve and bundle surface

1. Add `packages/resolver/src/errors/ResolveError.ts` and `packages/resolver/src/errors/BundleError.ts`, each extending `ApiDOMError` with the constructor shape and `@public` TSDoc of `src/errors/DereferenceError.ts`.
2. Add `packages/resolver/src/element-context/arazzo.ts` and `packages/resolver/src/element-context/openapi.ts`: one function per document kind that takes an element and merged `ApiDOMReferenceOptions` and returns `{ baseURI, mediaType, refSet }` by the rules `dereferenceElement` applies today (`retrievalURI` metadata, `resolve.baseURI`, child element seeded from `dereference.strategyOpts.parseResult`; media type from `mediaTypes.latest()` of the matching namespace). `baseURI` comes back `undefined` when no base is available, together with which scenario lacked it, so each caller throws its own error class with the existing message text. The OpenAPI module owns `isOpenApiElement` and the media-type inference now private to `src/dereference/openapi.ts`.
3. Make `dereferenceElement` in `src/dereference/arazzo.ts` and `src/dereference/openapi.ts` consume the context modules; behavior, thrown messages, and the existing dereference tests stay unchanged.
4. Add `packages/resolver/src/resolve/arazzo.ts` exporting `Options` (`PartialDeep<ApiDOMReferenceOptions>`), `defaultOptions` (parser resolvers and parsers plus the JSON, YAML and binary parsers, the four dereference strategies, and `resolve.strategies` holding `Arazzo1ResolveStrategy`, `OpenAPI2ResolveStrategy`, `OpenAPI30ResolveStrategy`, `OpenAPI31ResolveStrategy` from their `@speclynx/apidom-reference/resolve/strategies/*` subpaths), `resolve(uri, options)` (working-directory resolution of relative paths as in dereference, `resolve` from `@speclynx/apidom-reference/configuration/empty`, `isArazzoSpecification1Element` check on `refSet.rootRef.value.api`, `retrievalURI` metadata on that root parse result, every failure wrapped in `ResolveError` with `cause`) and `resolveElement(element, options)` (context module, `resolveApiDOM`, `ResolveError` wrapping).
5. Add `packages/resolver/src/resolve/openapi.ts` with the same shape for OpenAPI 2, 3.0 and 3.1.
6. Add `packages/resolver/src/bundle/arazzo.ts` exporting `Options`, `defaultOptions` (as in task 4 plus `bundle.strategies` holding `Arazzo1BundleStrategy`, `OpenAPI2BundleStrategy`, `OpenAPI30BundleStrategy`, `OpenAPI31BundleStrategy` from `@speclynx/apidom-reference/bundle/strategies/*`), `bundle(uri, options)` (path resolution, `bundle` from apidom-reference, Arazzo check on `parseResult.api`, `retrievalURI` metadata, `BundleError` wrapping) and `bundleElement(parseResult, options)` (throws `BundleError` unless `isParseResultElement`; context module for base URI and media type; builds a `File({ uri, parseResult, mediaType })`, picks the first strategy in `bundle.strategies` whose `canBundle(file, options)` returns true, runs `strategy.bundle(file, options)`; `BundleError` when no strategy matches or bundling fails).
7. Add `packages/resolver/src/bundle/openapi.ts` with the same shape for OpenAPI.
8. Export from `packages/resolver/src/index.ts`, following the existing aliasing blocks: `resolveArazzo`, `resolveArazzoElement`, `defaultResolveArazzoOptions`, `ResolveArazzoOptions`, `resolveOpenAPI`, `resolveOpenAPIElement`, `defaultResolveOpenAPIOptions`, `ResolveOpenAPIOptions`, `bundleArazzo`, `bundleArazzoElement`, `defaultBundleArazzoOptions`, `BundleArazzoOptions`, `bundleOpenAPI`, `bundleOpenAPIElement`, `defaultBundleOpenAPIOptions`, `BundleOpenAPIOptions`, `ResolveError`, `BundleError`, plus `export type { ReferenceSet } from '@speclynx/apidom-reference/configuration/empty'` so consumers can type the resolve result without a second import (mirrors the parser's `ParseResultElement` re-export).
9. Add `packages/resolver/test/resolve/arazzo.ts`, `test/resolve/openapi.ts`, `test/bundle/arazzo.ts`, `test/bundle/openapi.ts` with multi-file fixtures under `test/resolve/fixtures/` and `test/bundle/fixtures/` (an entry document with external `$ref`s and, for Arazzo, source descriptions; expected bundled documents as JSON). Each file covers: file system path to JSON and to YAML, relative path against the working directory, HTTP URL through `createHTTPServer`, `ParseResultElement` with `retrievalURI`, inline parse result with and without `resolve.baseURI`, a non-matching document and a missing file (`ResolveError` / `BundleError` with `cause`); the resolve files add the child-element scenario, the bundle files assert `toValue(result)` deep-equals the expected JSON and that a non-`ParseResultElement` raises `BundleError`.

## Group 2 — Package manifest

10. In `packages/resolver/package.json` set `"version"` to `1.0.1-alpha.2`, set `"@usearazzo/parser"` to `1.0.1-alpha.2`, and delete the `"private": true` line.
11. Run `npm install` at the repository root so `package-lock.json`'s `packages/resolver` entry records the new version and pin; commit the lockfile with the manifest.

## Group 3 — Documentation and constitution

12. Rewrite `packages/resolver/README.md` in `packages/parser/README.md`'s shape: centered heading, npm and license badges, logo; "What it does" with one paragraph each for dereference, resolve and bundle; an "At a glance" table listing all twelve functions (Takes / Returns) grouped by operation; the in-memory contract sentence (the plain functions take paths and URLs; parse objects and strings first and call the `*Element` variant with `resolve.baseURI`); Installation; Usage with one example per operation; the pointer `**[API reference](https://usearazzo.com/docs/resolver/)**`; Supported versions; the toolkit footer.
13. In `specs/tech-stack.md`: rewrite the "The resolver takes paths and URLs only" bullet under § Constraints and Conventions so it covers dereference, resolve and bundle, keeps "the resolver does not grow a `MemoryResolver`", and drops the claim that bundling is apidom-reference's job; in § Architecture Summary "Current maturity", list the resolver as published; in § Deployment and Operations "Error handling", add `ResolveError` and `BundleError` beside `DereferenceError`.
14. Append ` ✅` (a single space followed by the U+2705 checkmark) to the `## Phase 1 — Publish @usearazzo/resolver` heading in `specs/roadmap.md`, leaving the rest of the block untouched, per the lifecycle rule in `specs/roadmap.md`.
