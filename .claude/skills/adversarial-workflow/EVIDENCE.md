# Evidence — adversarial-workflow

Maintainer document. This file holds the measurements, field-run reports, open experiments, and revision history behind the rules in `SKILL.md`. It is **not** loaded during skill runs and nothing in it is an instruction to an executing model — read it when questioning a rule's basis, or before changing one. Every rule in `SKILL.md` that carries a "measured" or "field" tag resolves here.

## Benchmark

Legacy-code verification, 4 known-answer tasks × 3 independent Sonnet attempts, graded by Opus graders who re-ran every command:

- **12/12 PASS**, zero fabricated output under audit — including subtle inference (a schema-vs-table category error that made a grep structurally unable to match), search breadth, and cross-file contradiction detection. No controlled Opus baseline was run on the same grid; "Sonnet is sufficient" rests on these absolute results plus the informal same-session comparison two bullets down.
- **The gap was corrections, not detection.** On the one task requiring "and here's the right answer": 0/3 found it, 2/3 speculated wrongly. Sole basis for Opus corrections — and it does not separate tier from effort (see Open experiments).
- **The refuter layer caught what the tier missed.** Opus first-pass verifiers in the same session missed a filename-with-spaces `xargs` bug and a quoted-argument variant; refuters caught both. The architecture did more work than the model tier did. Whether it earns its *cost* is unmeasured — see Not measured.

## Field runs

Five workflow runs (plan review 19 agents, implementation review 14, doc-claims verification 10, PR-review-fix verification 9, PR #54 full review 30), plus one gate event:

- **Findings-axis refutation held**: 6/6 CONFIRMED at parity, and the findings materially improved the plan — a speculative base class dropped, a doc section forced into a full rewrite, an overstatement corrected. Run 3 recorded the first kill, and it was correct — both lenses reached CONTRADICTED on non-overlapping grounds (entailment: a count unsupported and generalized past what was probed; precision: the transcript did not reproduce). First direct evidence that the two axes are not redundant and that confirmation is not rubber-stamping; still n=1 kill, keep counting via SKILL.md §8.
- **The miss-challenge layer produced findings the primary finder did not — 5/5 runs.** This is why §3 makes it unconditional; an earlier draft gated it on a cheap-run flag and that was wrong. In runs 3 and 5 it was the *sole* source: every primary finder returned empty while the miss-challenges surfaced real, materially actionable defects. In run 6 it produced the single most important code defect of the run (the unguarded arbitration merge) while all four primary finders were returning findings.
- **Miss-channel numbers are unreliable (run 3):** four miss findings, substantively right, three mutually inconsistent file counts, one produced with no command run. Basis for the §3 rule that the orchestrator re-derives any figure it propagates from the unrefuted channel. Run 6 extended the unreliability from numbers to *scope*: a miss finding counted 9 tools "missing" from the entailment-lens denylist, but orchestrator re-derivation against the sub-agents docs showed the denylist pool-complete — the extras sit outside the documented pool the comment claims completeness over. First miss finding to dissolve on scope rather than arithmetic.
- **The entailment leak is observed (run 3):** one entailment call made 1 tool call under prompt-only denial. Basis for enforcing the lens structurally via `agentType` rather than prompt alone.
- **Shared-tree probe protocol held (run 3):** zero leaks, tree verified clean after — per-agent probe tags, create-and-delete in the same command, "ignore foreign `__probe_*` files" in every prompt.
- **A true claim was killed for its fabricated evidence (run 3):** a correct claim about a lint carve-out, supported by a transcript that did not reproduce; both refuters killed it, correctly, on evidence. Basis for the "a kill is not a clean bill" rule — read `discrepancies` on refuted findings, not just survivors.
- **Run 3 cost/reliability figures:** 10 agents, 355k subagent tokens, 114 tool calls, ~8.9 min, 0 agent failures. First fabrication-flag field hit (a finder's non-reproducing probe transcript). ## Corrections to earlier drafts

- An earlier draft budgeted the tool-free entailment calls at "~3k tokens"; a field measurement put one at ~24k (orientation pack + batched claims block dominate). §6 now carries the measured figure.
- An earlier draft gated the miss-challenge on a cheap-run flag; 3/3 field runs (the count at the time of that draft — the streak has continued in every run since, see Field runs) showed the layer producing findings the primary finder missed, so §3 makes it unconditional.

## Not measured

- Synthesis quality at any tier (n=4 runs reaching the stage: 2 outright failures, 2 schema-valid completions that both needed orchestrator repair; no head-to-head against orchestrator reconciliation in either direction).
- The parity rule itself — the benchmark above is Opus-grades-Sonnet, i.e. non-parity, and it worked. If ever measured, update SKILL.md §2.
- The cost structure: batching, the two-axis split, the arbitration gate, and the synthesis threshold are design choices made to control spend, not benchmarked ones.
- The depth gate (2026-08-01): the `mechanism_stated` rider as the trigger, its any-vote-flags polarity, and the no-re-refute asymmetry on deepen output are design choices. The §8 rider-calibration and bounce-count signals exist to audit them; n=1 downstream grading (3/15) is the only depth measurement so far. The live risk is that two always-on votes let through findings that three would have killed. Re-run the 4 known-answer set and compare drop counts before trusting the numbers.
- The §0 profiles (2026-08-07): `lean`'s `low`-effort finders, the always-skip synthesis, and the deferred-deepen default are spend choices, not benchmarked ones — see the 2026-08-07 revision note for what each must answer to.

## Open experiments

- **Deepen tier vs effort (§4; stage formerly CORRECTION).** The 0/3 correction measurement confounds tier with effort: the failing runs were Sonnet at *default* effort, and speculation-instead-of-testing is exactly the failure more thinking might fix. Opus stays the default because it's what was measured to work — and the 2026-08-01 gate widening raises the stakes in both directions: the stage is now a strictly larger Opus consumer (bigger saving if Sonnet-high closes the gap), and its mandate now includes root-cause depth (exactly where a weaker tier is most suspect). The experiment is one afternoon: rerun the 4 known-answer tasks with `model: 'sonnet', effort: 'high'` deepens, grading root cause and resolution, not just the corrected value. Re-opened by every Sonnet release — the candidate is a different, stronger model each time.
- **Does the deepen pass close the depth gap (§4)?** Baseline: 3/15 survivors bounced at resolution time (run 6, downstream grading above). Watch in-run `deepen.diagnosisIncomplete / deepen.run` and, decisively, the downstream bounce count routed back per §8. (2026-08-07: the §0 profiles add a deferred arm — bounce counts now compare per profile: no-deepen baseline vs deferred-on-demand vs inline.) Calibrate the `mechanism_stated` rider via `depthFlags` vs `deepen.onSymptomOnly`: near-zero flags means the rider gates nothing and the depth gap slips through on non-kill survivors; near-universal flags means it is a constant, not a gate, and the Opus spend is uncontrolled. **Escalation path, gated on evidence:** only if bounces persist at Opus *with the widened gate in place*, trial `model: 'fable'` on the deepen stage alone — the smallest-N, highest-leverage Opus consumer — weighing bounce reduction against 2× per-token cost ($10/$50 vs $5/$25 per MTok) and Fable's refusal classifiers on security-adjacent review content (a refused deepen becomes a null via `run()`, one more variance source). One variable at a time: do not stack the tier change on the gate change — that reproduces the tier-vs-effort confound above.
- **Can the entailment axis kill under the 2-vote quorum, or only dissent?** Watch `overreach.objections / upheld / overruled` (§8). A persistent `overruled > 0, upheld = 0` pattern means the overreach lens needs weight, not just a seat. First data (run 6): objections 2, upheld 1 (the objection carried through arbitration to a correct kill), overruled 1 — the axis can kill when arbitration agrees. n=1; keep counting.
- **Does the unrefuted miss channel need its own refutation round?** Watch `missChallenge.findings` plus your grading of them.
- **Does self-reported `kills_a_claim` need an audit?** Watch `contestedBy.*` + `deepen.*` (metric renamed from `corrections.*` in the 2026-08-01 revision) for inflation or starvation of arbitration and the Opus deepen spend it co-gates. First data (run 7): all 11 kill-flags were on genuine wrongness-assertions, but on a doc review that is most findings — the flag contested 11/16 findings and co-drove 13 deepens; watch for the same near-universality on future doc-review compositions.
- **Does the shared orientation pack need a verifier?** Open since the 2026-07-24 revision. First incident (run 6): the orchestrator's hand-excerpted runtime-contract file omitted the documentation's canonical pipeline example, and a finder built a survivor on exactly that gap (a "stage-1 argument unconfirmed" claim the full documentation settles) — an incomplete pack manufactured a finding two refuters then had no basis to kill. Weigh a pack verifier against the cost of refuters re-reading source docs.
- **A `blocking|material` severity filter on the correction gate** — proposed after run 3, declined: it stacks a second unaudited producer self-report onto the gate `kills_a_claim` already controls, and it never fired, so there is no evidence either way. Reconsider only with §8 data showing correction overspend.

## Revision notes

### 2026-10-05 — distributable packaging

Made the skill installable by people who never had the original plugin. The 2026-08-01 port bundled the agent but still relied on a manual copy into `.claude/agents/`, and a missing copy degraded silently (every lens vote `missing`, all other stages paid). Changes: `install.sh` plus a Windows `install.bat` with the same flags and behavior (CRLF, goto-only flow so paths with `)` or `!` survive; `.gitattributes` pins both scripts' line endings; the .bat was not executed on Windows at release, only reviewed) (user or `--project` scope; installs the skill folder and the agent, `--check` for status, refuses to overwrite a differing agent without `--force`, `--uninstall`); SKILL.md gains a Setup section ahead of the gates; the skeleton gets a `LENS_AGENT` constant (one place to change for a plugin-namespaced type) and a lens preflight, one sonnet/low `agent()` call with `agentType: LENS_AGENT` before Find, that throws on failure so a missing lens aborts the run before anything is spent. §6 budget gains its `+1`; the worked-example counts moved by one. Runtime fact behind the restart requirement, probed the same day: an agent definition written to `~/.claude/agents/` mid-session was rejected by the Agent tool as unknown (`Agent type '…' not found`), and the registry list did not include it, so definitions load at session start only. Not verified: whether the Workflow runtime's `agentType` lookup shares that snapshot (assumed, since it resolves from the same registry), and the preflight's exact error text on an unknown type, which is why the guard aborts on any failure rather than matching a message.

### 2026-08-07 — §0 profiles: invocation-time spend parametrization

Motivated by field use (the maintainer's typical runs were too slow and token-heavy at full spend) and by run 7's rider-calibration data: on doc-review content `mechanism_stated` ran near-universal (depthFlags 10/16, 13 deepens ≈ 39% of run tokens) — the depth gate behaving as a constant, exactly the §8-named failure mode. Change: a `PROFILE` block (`lean` / `standard` / `deep`) now sets worker effort, deepen mode, and the synthesis threshold at invocation; SKILL.md gained §0, and the skeleton reads everything profile-dependent from the one block.

The deepen default moved from inline to **deferred**: the §4 gate still computes in every profile (the rider rides the refuter schema at zero cost), but the run returns `deepenCandidates` unspent and the Opus pass becomes an on-demand follow-up workflow (one Opus/`high` agent per selected finding, same `deepenPrompt`/`DEEPEN` schema, orientation pack reused, findings via `args` — never via resume, which would invalidate the agent-call prefix cache). `deep` restores the previous behavior exactly; the pre-profile pipeline ≡ `deep`. New metric: `deepen.deferred`; new result fields: `profile`, `deepenCandidates`; new §8 signal row for candidates-deepened-on-demand per profile.

Unmeasured, by design of the change:

- `lean`'s `low`-effort finders — the 12/12 benchmark ran at `medium`; re-run the known-answer set at `low` before trusting lean on anything durable.
- Deferred deepen vs the depth gap: the 3/15 bounce baseline was measured with *no* deepen stage; run 7 ran inline (downstream grading still pending). Deferred adds a third arm. Bounce counts routed back per §8 now carry the run's profile — that per-profile comparison, not any in-run signal, decides whether the deferred default holds.
